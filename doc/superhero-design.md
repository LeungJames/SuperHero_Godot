# SuperHero 设计说明（港口吊塔 · 纵向下行 · 可游玩原型）

> 本文档是对 [superhero.md](./superhero.md) 的补全与落地说明，不修改原文。
> 目标读者：开发者本人（及后续接手的人），按本文即可直接开工。
>
> **文档状态**：本轮 12 项待确认问题已全部拍板，文中不再保留"默认方案（待确认）"标记。
> 已确认结论已按条目落到各章节，汇总见 [§12 已确认决策记录](#12-已确认决策记录)。

- 引擎：Godot 4.7（Forward+，Windows 下 D3D12 驱动，Jolt 物理）
- 语言：C#（assembly `SuperHero`，net8.0）
- 平台：PC 单机
- 本阶段目标：**一局可完整游玩的港口关卡**——从吊塔顶向下推进、手枪对射、清空敌人即胜利，直升机撤离作为收尾演出

## 已确定设定（用户确认，不再作为默认方案）

1. 敌人全部持枪，**不存在近战敌人**。
2. 本场景中所有人（玩家与敌人）**只有手枪这一种枪械**，没有第二把武器。
3. 玩家**全程不能回血**：没有自动回血，也没有医疗包 / 治疗道具。
4. 交战节奏为"一枪一命"级别的高致命性：失误代价极高，失败即重开。
5. 关卡主线是**纵向下行**：从吊塔顶出发，一路向下穿越塔身、脚手架、集装箱屋顶，最终抵达港口地面。
6. 途中包含**必须跳跃才能通过**的段落，考验跳跃操作。
7. 胜利条件是**全歼即胜**：最后一名敌人死亡时立即判定胜利；直升机降落与登机是纯演出，不参与胜负判定。
8. 需要**简单的第一人称手臂**（低模，握枪姿态用程序化位移，不做骨骼动画）。
9. 用户不提供任何外部素材：**音效全部由程序生成**，模型由 Blender 自制。

## 1. 产品与体验目标

### 1.1 一句话定位

黄昏港口的高空吊塔顶出发，在格构塔身、脚手架与集装箱屋顶之间跳跃下行，
用一把 12 发手枪清掉沿途 8 个持枪黑帮；落到地面时黄昏全景铺开，战斗进入高潮，
清场即胜利，随后直升机降落、自动登机，作为不可跳过的收尾演出。

### 1.2 体验支柱

| 支柱 | 具体表现 | 验收方式 |
| --- | --- | --- |
| CS 式机动 | 无冲刺惯性拖沓感，落地干脆，跳跃可越矮掩体，移动射击散布惩罚明显 | 手感上"停得住、跑得动、打不准" |
| 纵向下行 | 从 42m 塔顶一路降到地面，每层结构不同、每层都有战斗与跳跃 | 全程有明确"往下走"的方向感 |
| 跳跃考验 | 缺口从 1.8m 递进到 3.2m，失败会落到下层承接平台并摔伤 | 跳跃段有难度曲线，不是装饰 |
| 高程叙事 | 塔顶视野辽阔偏冷，越往下雾越浓、光越金，落地时全景铺开 | 下到地面那一刻有"豁然开朗"的视觉冲击 |
| 手枪对枪 | 主要交战距离 8–15m，双方靠掩体换弹、探头、抢第一枪 | 站着不动对枪必输 |
| 高致命性 | 玩家 4 发中弹即死；爆头一枪毙敌；弹匣只有 12 发 | 一次判断失误就到结算界面 |
| 美漫低模 | 硬钢笔黑描边 + 明快纯色块，低多边形 | 画面像漫画分镜 |
| 短局可重玩 | 单局 4–6 分钟，死亡到重新开始 ≤2 秒 | 连续重开 5 次无需回桌面 |

### 1.3 本阶段明确不做

- 不做多人、不做存档、不做关卡选择、不做载具驾驶
- **不做第二把武器、不做武器切换、不做拾取武器**
- **不做回血、不做医疗包、不做护甲、不做任何生命恢复机制**
- **不做近战敌人、不做敌人近战攻击**
- 不做手雷、玩家近战、技能、道具背包
- 不做攀爬/绳索滑降系统（下行只靠**走、跑、跳、梯子**）
- 不做开火/换弹的第一人称骨骼动画：手臂与手枪用程序化位移表现（已确认需要简单手臂）
- 不做复杂物理破碎、布娃娃骨骼

## 2. 玩法循环与完整流程

### 2.1 单局流程

```
启动游戏
  │
  ▼
mainScene.tscn 加载（无开场动画，直接站在塔顶）
  │
  ▼
[Playing] 出生塔顶 Y=42m，鼠标锁定，HUD 显示 8/8 剩余敌人
  │
  ├── 逐层向下：塔顶 → 脚手架 → 运输臂 → 集装箱屋顶 → 港区地面
  │      每层有敌人、有跳跃段、有摔伤风险
  │
  ├── 全部敌人死亡 ──────────────┐
  │                              ▼
  │                      [Victory] 全歼即胜利
  │                  冻结输入 → 直升机降落演出（不可跳过）
  │                  无线电 → 8s 降落 → 自动登机 → 淡出
  │                              ▼
  │                         结算面板
  │
  └── 玩家生命值 ≤ 0 / 落水 / 摔死 ──┐
                                    ▼
                              [Defeat] 阵亡
                                    │
                    Enter / 点击"重新开始"
                                    ▼
                          ReloadCurrentScene()
```

### 2.2 状态机定义

`GameManager` 持有枚举 `GameState { Playing, Victory, Defeat }`，只允许从 `Playing` 迁移出去。

| 状态 | 进入条件 | 玩家输入 | HUD | 退出方式 |
| --- | --- | --- | --- | --- |
| `Playing` | 场景 `_Ready` 完成 | 全部开放 | 准星 / 血条 / 弹药 / 剩余敌人数 / 当前目标 | 全歼 → `Victory`；死亡 → `Defeat` |
| `Victory` | `EnemyRegistry.AliveCount == 0` | 冻结（进入胜利演出） | 目标条"区域清空"，战斗 HUD 随后淡出 | 演出结束 → 结算面板 |
| `Defeat` | 生命值 ≤ 0 / 落水 / 摔死 | 冻结，鼠标解锁 | 结算面板：阵亡、击杀 x/8、存活时间、死亡高度/位置 | 重新开始 → `ReloadCurrentScene()`；退出 → `Quit()` |

> **胜利在最后一名敌人死亡时立即成立**，直升机降落与登机都是纯演出，不参与胜负判定。
> 因此不存在"撤离途中被打死"的失败分支：进入 `Victory` 后不会再回到 `Defeat`。

### 2.3 胜利演出（全歼后，不可跳过）

胜利判定在最后一名敌人死亡时立即完成，之后播放一段不可跳过的收尾演出。

| 步骤 | 时间（累计） | 表现 |
| --- | --- | --- |
| 最后一名敌人死亡 | 0.0s | 立即进入 `Victory`，冻结玩家输入 |
| 横幅 | 0.2s | "区域清空 · 撤离直升机抵达中" |
| 无线电 | 0.4–1.4s | 无线电杂音 + 字幕 |
| 直升机接近 | 1.4–9.4s | 从海面方向沿曲线飞入，旋翼声渐强，探照灯亮起 |
| 降落 | 9.4s | 降落在栈桥尽头的停机坪 `(10, 0, -50)` |
| 自动登机 | 9.4–11.4s | 镜头切到侧向机位，玩家角色自动走向舱门并进入 |
| 淡出 | 11.4–12.4s | 画面淡出至米白，螺旋桨声拉远 |
| 结算 | 12.4s | 弹出结算面板 |

- 演出总时长约 **12.5s**，期间不接收移动/射击输入，`Esc` 不打开暂停。
- 玩家不需要走到停机坪，也**不存在登机触发区或登机按键**。
- 演出期间玩家不会受到任何伤害（此时已无敌人），因此**不存在"全歼后死亡"的失败情况**。
- 演出时长只影响观感与重玩节奏，不影响胜负逻辑。若后续想缩短重玩循环，只需调整 `VictorySequenceConfig` 的时长。

### 2.4 关键时序

| 事件 | 处理 | 时长 |
| --- | --- | --- |
| 最后一个敌人死亡 | 立即进入 `Victory` 并开始胜利演出 | 0.0s |
| 胜利演出 | 无线电 + 直升机降落 + 自动登机 + 淡出 | 约 12.5s |
| 玩家死亡 | 禁用控制器 → 相机下沉 + 去饱和 → 弹结算 | 1.0s |
| 落水 / 摔死 | 同死亡流程，结算面板标注死因 | 1.0s |
| 点重新开始 | `ReloadCurrentScene()`，单局状态随场景重建归零 | < 0.5s |

### 2.5 失败即重开（"一枪一命"节奏的配套）

高致命性 + 跳跃坠落，死亡必须**便宜**。

| 规则 | 做法 |
| --- | --- |
| 无检查点 | 一局只有一个起点（塔顶），死亡即整局重来 |
| 死亡演出极短 | 1.0s 内完成镜头下沉 + 去饱和，立即出结算 |
| 重开零摩擦 | 结算面板默认焦点在"重新开始"，`Enter` 或鼠标左键直接重开，无二次确认 |
| 全量重置 | 场景 reload 自然重置血量、弹药、敌人、计时与高度进度 |
| 无惩罚 | 不扣分、不锁关卡、不播片头 |
| 失败信息有用 | 结算显示"死在哪一层 / 还剩几个敌人 / 是坠落还是中弹" |

> 目标：**从死亡到能重新操作，不超过 2 秒。**

### 2.6 暂停

- `Esc` 切换 `SceneTree.Paused`（暂停 / 重新开始 / 退出）。
- 结算界面与胜利演出期间不允许暂停，避免打断演出或状态叠加。
- 暂停期间玩家、敌人、特效 `ProcessMode = Pausable`；HUD 与暂停面板 `WhenPaused` / `Always`。

| 重力 | 18 m/s² | 落地干脆 |
| 地面加速度 | 60 m/s² | 约 0.08s 达到全速 |
| 地面摩擦 | 50 m/s² | 松开按键约 0.1s 停住 |

| 鼠标灵敏度 | 0.12 °/像素（可调） | ADS ×0.7 |
| 身高 / 碰撞 | 胶囊 r=0.35m，高 1.8m | 相机 y=1.62m |

### 3.2 跳跃能力与关卡尺寸的对应关系

| 起跳状态 | 水平距离 | 关卡用法 |
| --- | --- | --- |
| 静步起跳（2.2 m/s） | ≈1.2m | 不用 |
| 默认速度起跳（4.8 m/s） | ≈2.67m | 1.8–2.4m 缺口（多数） |
| 冲刺起跳（6.2 m/s） | ≈3.45m | 2.8–3.2m 缺口（难点） |
| 冲刺起跳 + 1m 上升 | ≈2.2m | 需要同时上跳的段落 |

**关卡设计硬规则**：

1. 缺口按"冲刺起跳距离 × 0.93"设计，最宽 3.2m，绝不出现必须极限跳才能过的位置。
2. 所有落点平台尺寸 ≥2.5m × 2.0m，不做针尖落脚。
3. 需要上升的段落，单级高度 ≤0.6m（跳跃上限 0.69m，留余量），超过则改为梯子或斜坡。
4. 每个跳跃段前必须有 ≥4m 的助跑空间。
5. 跳跃段不允许同时被敌人射击（见 §6.6），否则"跳跃 + 对枪"会变成不可控死亡。

### 3.3 移动手感要点（实现约束）

1. **自定义速度积分**（`Velocity` + 加速/摩擦），不要 `Input.GetVector` × 速度。
2. 落地时垂直速度 < -6 m/s 播放落地音效 + 相机下沉 0.05m。
3. 贴墙滑行不损失水平速度。
4. 台阶 ≤0.25m 或加斜坡；可跳越的低掩体统一 0.5–0.6m。
5. 塔外沿必须有护栏或碰撞墙，只有设计好的跳跃口开放。
6. **土狼时间与跳跃缓冲必做**，否则高空跳跃段会非常挫败。

### 3.4 坠落与摔伤（纵向下行的核心规则）

**摔伤公式**：

```
落差 = 本次离地后的最大下落距离（米）
if 落差 <= 4.0:     伤害 = 0
else:               伤害 = min(100, (落差 - 4.0) * 14)
```

| 落差 | 伤害 | 结果（满血） |
| --- | --- | --- |
| ≤4m | 0 | 安全 |
| 5m | 14 | 轻伤 |
| 6m | 28 | 轻伤 |
| 8m | 56 | 重伤 |
| 10m | 84 | 濒死 |
| 11.2m+ | 100 | 死亡 |

**失败的兜底设计**（关键，避免高空跳跃变成"错一次就重开"）：

| 情况 | 处理 |
| --- | --- |
| 跳跃失败，落到下方 3–6m 的承接平台 / 防护网 | 扣 0–28 血，**从该层继续向下**，不需要重开 |
| 落到下一层主路线平台 | 扣 28–56 血，仍可继续推进 |
| 从 >11m 直坠地面 | 死亡 → 结算 |
| 落水 | 死亡 → 结算（标注"落水"） |
| 摔伤后继续失误 | 血量累积下降，最终死亡重开 |

- 塔身每 **6–8m** 设置一层承接平台或防护网（视觉上就是脚手架层板/安全网），位置与主路线错开，保证失败时不会直接坠到地面。
- 承接平台本身也是"下层路线"的一部分：摔下去之后不用回头爬，直接沿当前层继续向下。
- 摔伤时：红屏 + 镜头下沉 + 落地音 + 0.4s 移动速度减半（踉跄），不做长时间硬直。
- 水深判定：`GlobalPosition.Y < -1` 且不在栈桥碰撞范围内 → 落水死亡。

### 3.5 受击反馈

| 反馈 | 参数 |
| --- | --- |
| 红屏 | 透明度 = 伤害 / 100 × 0.8，0.5s 淡出 |
| 镜头抖动 | ±0.45°，0.4s 回正 |
| 受击方向 | 屏幕边缘 4 方向红色弧光 0.6s（无回血时，必须知道子弹从哪来） |
| 低血量 | HP ≤ 50 心跳音；HP ≤ 30 持续红晕 + 去饱和（饱和度 0.75） |
| 受伤音 | 男性闷哼，随机 3 个变体 |

### 3.6 死亡

- HP ≤ 0 → 禁用输入 → 相机 0.5s 下沉 0.5m、侧倾 8°、去饱和 → 1.0s 后 `EnterDefeat(死因)`。
- 死因三种：`Gunshot` / `Fall` / `Drown`，用于结算文案。
- 不做布娃娃、不可复活。

## 4. 武器（单手枪）

### 4.1 只有一把枪

玩家与所有敌人使用**同一型号手枪 P-9**。玩家侧数值更强，敌人侧见 §5。

- 无副武器、无武器槽、无切枪、无拾取武器。
- 玩家出生即持枪。
- `1` / `2` / `Q` 不占用键位。

### 4.2 玩家手枪数值

| 属性 | P-9 手枪 |
| --- | --- |
| 射击模式 | 半自动（必须松开再按） |
| 基础伤害（躯干） | 40 |
| 爆头倍率 | ×2.5 → **100 伤害，一枪毙敌** |
| 四肢倍率 | ×0.75 → 30 |
| 射速 | 5.5 发/秒（182ms） |
| 弹匣容量 | 12 |
| 起始备弹 | 36（3 个弹匣） |
| 备弹上限 | 60 |
| 换弹时间 | 2.0s |
| 腰射散布 | 1.2° |
| ADS 散布 | 0.25° |
| 开镜时间 | 0.15s |
| ADS 移速倍率 | 0.55 |
| 每发后坐（垂直） | 1.6° |
| 每发后坐（水平随机） | ±0.35° |
| 后坐回正速度 | 14°/s |
| 连续射击后坐累加 | 每发 +10%，上限 ×2.0 |
| 全伤害距离 | 25 m |

| 穿透 | 无 |

> 躯干 3 发击杀 100 HP 敌人，爆头 1 发。半自动 + 12 发，逼玩家点射与爆头。

### 4.3 伤害衰减公式

```
t = clamp((距离 - 全伤害距离) / (最低伤害距离 - 全伤害距离), 0, 1)
最终伤害 = 基础伤害 * lerp(1.0, 最低伤害倍率, t) * 部位倍率
最终伤害 = round(最终伤害)
```

25m 内满伤害，50m 外躯干 24 / 爆头 60（不再一枪毙敌）。

### 4.4 命中判定

- 纯 hitscan（`PhysicsDirectSpaceState3D.RayCast`），无实体子弹。
- 射线起点＝相机中心；视觉弹道从枪口画到命中点。
- `CollisionMask = 1 | 4`（世界 + 敌人命中盒），`CollideWithAreas = true`。
- 表现：枪口闪光 0.05s + 拖尾 0.06s + 命中火花/灰尘。

### 4.5 后坐力模型

- 后坐写入**相机偏移量**，不改玩家实际朝向。
- 每发 `pitchOffset += 1.6°`，`yawOffset += random(-0.35°, +0.35°)`。
- 每帧以 14°/s 线性回正。
- ADS 时后坐 ×0.7。

### 5.2 高度带来的视野差异

纵向下行意味着**敌人常常在玩家上方或下方**，感知必须处理垂直方向。

| 情况 | 规则 |
| --- | --- |
| 敌人在高处、玩家在低处 | 有效视野 **+8m**（俯视开阔），发现更快 |
| 敌人在低处、玩家在高处 | 有效视野 **×0.6**，且必须在 ±35° 垂直视野锥内 |
| 垂直落差 >20m | 不进入 `Combat`，只进入 `Alert` 并靠近（打不准，也不该打） |
| 玩家在空中（跳跃中） | 敌人对其命中散布 +2°，避免"空中被秒" |
| 隔着格构/防护网 | 视为半遮挡：可见但命中判定按实际碰撞体，格构本身不挡子弹 |

### 5.3 行为状态机

```
Patrol ──看到玩家/听到枪声──▶ Alert ──有视线──▶ Combat
  ▲                              │                 │
  │                              │ 到达声源无线索   │ 失去视线 >1s
  └──── Search 超时(4s) ◀─────────┴─────────────────┘
                                      Search（前往最后已知位置，环视）
```

| 状态 | 进入条件 | 行为 | 退出条件 |
| --- | --- | --- | --- |
| `Patrol` | 初始 / 搜索失败 | 沿巡逻点循环，到点停 1–2s 环视 | 感知到玩家 → `Alert` |
| `Alert` | 视野内出现玩家 / 30m 内听到枪声 | 停 0.30–0.45s 面向目标，播"发现"音效 | 有视线 → `Combat`；2s 无视线 → `Search` |
| `Combat` | 有视线且在交战距离内 | 街头枪手压上；守卫守掩体探头射击 | 失去视线 1s → `Search` |
| `Search` | 失去视线 | 前往最后已知位置，环视 2s | 重见玩家 → `Combat`；4s 超时 → `Patrol` |

### 5.4 感知实现要点

- 视觉：`IntersectRay`（眼位 → 玩家胸口），命中世界层视为遮挡；同时判定距离、水平角、垂直角。
- 听觉：`NoiseEmitter.Emit(position, radius)`，敌人按距离订阅判断。
- 敌人之间不共享情报（简化）。
- 巡逻点用子节点 `Marker3D` 顺序表达；为空则原地驻守。
- `NavigationAgent3D` + `NavigationRegion3D` 烘焙，**每层单独烘焙或使用同一导航网格的多层连通**；关闭避让，靠碰撞挤开。
- 敌人在脚手架上**不跳跃**：巡逻点必须由走道/梯子连通。这一点在关卡阶段必须先跑通导航再放敌人。
- 守卫的探头用 `CoverPoint` / `PeekPoint` 两个锚点交替。

### 6.5 跳跃段设计（难度递进）

| 编号 | 位置 | 缺口 | 落差 | 所需操作 | 失败后果 |
| --- | --- | --- | --- | --- | --- |

**难度递进原则**：

3. J4 是全关唯一需要"冲刺 + 精准落点"的位置，周围有防护网兜底。
4. 所有跳跃段落地后 2 秒内不会遭遇敌人（先落地、再交战）。
5. 跳跃段不设置计时、不设置一次性机关，纯粹考操作。

### 6.8 黄昏光照与视野的高度叙事

同一场景、不同高度要有明显不同的观感，用雾、天空占比、逆光强度三者叠加实现。

| 高度 | 画面构成 | 雾密度 | 环境光能量 | 感受 |
| --- | --- | --- | --- | --- |
| 40m+（塔顶） | 天空占 60%，海面在远处发亮，结构投影长 | 0.004 | 1.15 | 明亮、开阔、微冷，像"还没到黄昏" |
| 25–40m（脚手架） | 天空 40%，脚手架剪影切割画面 | 0.007 | 1.05 | 暖色开始渗入 |
| 10–25m（运输臂/屋顶） | 天空 25%，集装箱边缘被逆光描亮 | 0.010 | 0.95 | 金色开始压过来 |
| 0–10m（地面） | 天空 15%，长影穿过结构，海面全景铺开 | 0.014 | 0.90 | 浓金、逆光、全景高潮 |

**实现方式**：

- 一个 `WorldEnvironment`，由 `EnvironmentController.cs` 根据玩家当前高度插值 `fog_density` 与 `ambient_light_energy`（见 §9.3）。
- 太阳角度固定（X=-9°, Y=-38°），不随高度变化——短局内太阳不会真的移动，靠雾与遮挡制造"黄昏浮现"。
- 塔顶视野中必须能看到：远处海面高光带、货轮剪影、港口吊机群轮廓。
- 地面层必须保证：从栈桥朝北看是"海面 + 落日 + 停机坪"的完整构图。

| 仓库货架 | 12 × 1.2 × 3.5 m | 4 | 室内遮挡 |
| 脚手架设备箱 | 1.5 × 1.0 × 0.9 m | 8 | 高空层唯一掩体，兼作跳跃落脚点 |

### 6.10 关卡搭建规则

1. 每层单独验证导航连通（敌人不跳，走道/梯子必须真的连通）。
2. 所有平台边缘有护栏或碰撞墙，只留设计好的跳跃口。
3. 平台高差 ≤0.25m 用斜坡，0.4–0.6m 用跳跃段，>0.6m 必须走梯子或斜坡。
4. 光照从西北打来，保证塔顶看到海面逆光、地面看到长影。
5. blockout 用 Godot 基础几何（`BoxMesh`）搭建，美术阶段整体替换，**坐标与碰撞位置不变**。
6. 塔身格构（桁架）在 blockout 阶段用细长方体占位，注意**不要挡住跳跃路线与敌人视线**。

### 8.6 Blender → Godot 流程要点

1. **连接**：先用 Blender MCP 的 `get_scene_info` 确认 Blender 已连接。
2. **单位与轴向**：场景单位设为米；角色/道具在 Blender 中**面向 -Y**，导出后即 Godot 的 -Z 前向。
3. **原点**：道具原点在底面中心，角色在脚底，**吊塔原点在塔基中心（地面 Y=0）**，方便在关卡里对位。
4. **材质**：只用 Principled BSDF，Metallic=0，Roughness=0.85，纯色块。
5. **描边不要做进 Blender**：Freestyle / Solidify 描边不会随 glTF 导出，统一在 Godot 用 shader。
6. **碰撞**：需要碰撞的网格加 `-col` / `-colonly` 后缀；塔身格构**不要给每根杆都加碰撞**，只给走道、平台、梯子加，其余用简化碰撞盒。
7. **导出**：`glTF 2.0 (.glb)`，勾选 `Apply Modifiers`、`+Y Up`，输出到 `art/models/`。
8. **Godot 导入**：`Root Type = Node3D`；导入结果作为子节点挂进场景，逻辑节点留在 Godot 侧。
9. **验收**：缩放 1.0、材质不丢、法线不翻、朝向正确、描边闭合、**平台尺寸与 blockout 一致**。
10. **版本管理**：`.blend`、`.glb`、`.import` 都提交；`.godot/`、`bin/`、`obj/` 忽略。

### 8.8 音效（全部程序生成，不使用外部素材）

用户不提供任何素材，所有音频由代码在运行时合成，没有 `.wav` / `.ogg` 文件依赖。

| 音效 | 合成方式 | 时长 | 备注 |
| --- | --- | --- | --- |
| 手枪射击 | 白噪声脉冲 + 80Hz 低频正弦衰减 | 0.25s | 每次随机音高 ±5% |
| 空仓 | 两次短促方波点击（约 2kHz） | 0.12s | |
| 换弹 | 3 段噪声脉冲（卸匣 / 上匣 / 拉套筒） | 0.5s | 与 2.0s 换弹时间对齐 |
| 命中敌人 | 低频闷响 + 短噪声 | 0.10s | |
| 爆头 | 明亮金属"叮" + 低频 | 0.15s | |
| 玩家受击 | 低频闷响 + 呼吸噪声 | 0.20s | |
| 脚步 | 带通滤波噪声脉冲 | 0.08s | 静步时静音 |
| 落地 / 摔伤 | 低频冲击 + 碎石噪声 | 0.20s | 音量随落差增大 |
| 敌人发现 | 锯齿波 300→600Hz 上升音 | 0.30s | |
| 环境风声 | 粉红噪声 + 缓慢低通扫频（循环） | 2–4s | 随高度调整音量 |
| 海浪 | 低频噪声 + 周期包络（循环） | 2–4s | 地面层更明显 |
| 直升机 | 20Hz 调制低频 + 噪声（循环） | 2–4s | 胜利演出期间淡入 |
| 无线电 | 带通噪声 + 短方波 | 0.60s | |

**实现要点**：

1. `ProceduralAudio.cs` 在启动时合成短音效为 `AudioStreamWAV`（16-bit / 44.1kHz / mono），缓存进字典，播放时零分配。
2. 连续音（风、海浪、旋翼）预生成 2–4s 循环片段，用 `AudioStreamPlayer` 循环播放，避免 `AudioStreamGenerator` 的实时填充开销。
3. 只求"可辨识"，不追求写实；音量统一走 `SFX` / `Ambient` 两条 `AudioServer` 总线。
4. 调用方只依赖 `Sfx.Play(SfxId)` 之类的接口；以后若换成真实素材，只需替换 `ProceduralAudio` 的提供源，调用方不改。

## 9. 技术架构

### 9.1 原则

- **业务逻辑全部在 C#**；`.tscn` 只做节点装配，自定义 `Resource` 只承载数值与引用。
- `[Export]` / `[GlobalClass]` 仅用于让编辑器能配置数据；跨系统通信用普通 C# `event`。
- 数值不硬编码，走 `PlayerData` / `PistolData` / `EnemyData` / `VictorySequenceConfig` 四份 Resource。
- 只有一把武器，**不做武器槽/武器基类抽象**。

### 9.4 伤害与死亡数据流

```
开火 → HitscanResolver RayCast
     → 命中 Collider → 向上找 Hitbox
     → Hitbox 计算部位倍率 → DamageInfo{伤害, 命中点, 方向, 是否爆头}
     → 父级 EnemyHealth.TakeDamage
     → 死亡 → EnemyRegistry 注销 → 存活数 -1 → 为 0 时触发全歼事件
     → GameManager.EnterVictory() → VictorySequenceController.PlayVictorySequence()
```

```
坠落 → FallTracker 记录离地最大高度
     → 落地 → 落差 > 4m → PlayerHealth.TakeDamage(Fall, (落差-4)*14)
     → 继续游戏（不重置位置）

落水 → WaterKillVolume 检测 → PlayerHealth.Kill(Drown)

胜利成立后不再判定任何失败（演出期间玩家不可能受伤）
```

`DamageInfo` 为 `readonly struct`，避免 GC。
