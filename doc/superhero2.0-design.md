# SuperHero 2.0 设计说明（施工级）

> 本文是 [superhero2.0.md](./superhero2.0.md) 的施工级展开，体例参照 [superhero-design.md](./superhero-design.md)。
> 长期愿景见 [superhero.md](./superhero.md)，方向取舍见 [vision-roadmap.md](./vision-roadmap.md)。
> 本文只描述 2.0 要做什么、怎么做、怎么验收，不改动 1.0 的任何文档。

---

## 已确定决策（不再讨论）

1. **不加新关卡**，只打磨现有三章：港口、赤蛇工厂、铁锚据点。
2. **天赋必须真正改变玩法**，不做小幅数值强化；由此产生的关卡改造单列一节（§9）。
3. **Boss 只在第三章**，且是完整体：血量、三阶段行为、专属表现，不只是演出。
4. **敌人协同是第一个实施项**。
5. **加点资源来自三维评级**：战术机动 / 武器大师 / 忍杀，各自评级、各自给对应天赋线的点数。
6. **评级 C=1 / B=2 / A=3 / S=4，再乘关卡系数**；评分只看风格与效率，**不把剩余血量计入**，避免与零回血冲突。
7. 三维**分开评级**，不合成总评；加点按**历史最佳评级只发一次**，重玩只刷记录、提升评级时补差额。
8. 天赋**可以重置**：只在章节外重置，代价可配置（默认前 1 次免费，之后每次扣 2 点，见 §5.4）。
9. **砍掉子弹时间**；钩锁、二段跳、激光剑气三项必做。
10. 枪战节奏完全由敌人协同（§2）控制，设计中不保留"靠子弹时间救场"的假设。
11. **难度不影响评级**：评级阈值固定，不区分难度。
12. **跨章武器除港口外不限制**：港口任何入口恒为 P-9 + 刀，跨章武器在港口不生效；其余章节可用已解锁武器，按章节阈值给分，后期武器打前面关卡不加分也不扣分。
13. **Boss 战计入击杀类指标**（武器大师的命中/爆头/空仓），**不计入高度类地形指标**（机动的动作密度/垂直位移），时间仍计入通关时间。

## 1. 目标与范围

### 1.1 2.0 的一句话目标

让三章从"能通关"变成"值得重玩"：敌人像一支队伍，潜行有真正的第二条路，天赋能改变通关方式，第三章有一个真正的 Boss。

### 1.2 范围边界（明确不做）

| 不做 | 原因 |
| --- | --- |
| 新关卡、新章节 | 2.0 只打磨现有三章 |
| 新敌人模型（Boss 除外） | 复用盐帮打手 / 哨位枪手两套模型变体 |
| 回血、护甲、医疗包 | 零回血是硬约束，天赋与难度都不得触碰 |
| 港口章节出现手枪与近战以外的武器 | 武器按章节解锁，首次通关流程不变 |
| 联机、排行榜、成就系统 | 超出单人战役范围 |
| 重写渲染管线 | 只做性能与表现层优化 |
| 1.0 文档的数值回改 | 1.0 文档保持原样，2.0 以本文为准 |

### 1.3 2.0 完成后玩家应该感觉到什么

1. **敌人不再是一个个靶子**：有人压枪、有人绕后，打死一个之后压力会变化，而不是简单少一个目标。
2. **每关有第二种走法**：可以整关不触发警报，也可以正面硬吃，两条路都成立。
3. **天赋改变打法**：点了钩锁和空中冲刺之后，同一张地图的走法明显不同；忍杀线让近战从"应急"变成"主玩法"。
4. **结算有话说**：三枚评级徽章能解释"这一局我打得怎么样"，而不是只看用了多久。
5. **第三章有终点感**：Boss 有阶段、有专属演出，打完像一个章节的收尾。

### 1.4 工程现状基线（写方案的前提）

| 模块 | 现状 |
| --- | --- |
| 章节 | 三章可连续通关；结算面板有下一章入口；第三章为终局 |
| 玩家 | 第一/第三人称切换、滑铲、蹬墙跑、翻越、边缘攀爬、处决、近战枪托、暗杀、零回血 |
| 摔伤 | **6m 起算，每米 14 点**（以当前实现为准，1.0 文档的 4m 起算已过期） |
| 武器 | P-9、ST-9、AR-5、M-870、SV-98，按章节解锁，自动换弹 |
| 敌人 | 两种模型变体（盐帮打手 / 哨位枪手），状态机 Patrol/Alert/Combat/Search，视觉 + 听觉感知，掩体逻辑，AlertDirector 按高度层刷增援 |
| 已有 | 程序化音效、漫画化拟声词与分镜、HUD、暂停菜单 |
| 没有 | 存档系统、设置菜单、手柄支持、天赋系统、任何 Boss、任何收集品 |

> 本文凡是需要现有场景坐标、敌人数量、实测时长的地方，一律标"待定"并说明缺什么，不编造。

## 2. 敌人协同

### 2.1 目标体验

一个小队 2–3 人，形成"压制—包抄—支援"的分工；玩家能通过无线电与拟声词读懂协同，而不是被莫名其妙地打死。

### 2.2 小队编制

| 项 | 规则 |
| --- | --- |
| 小队规模 | 2–3 人：1 名队长 + 1–2 名成员 |
| 编制来源 | 关卡里的 `SquadSpawnPoint`，不再按单个敌人摆放 |
| 小队数量 | 每关 4–6 个小队（现存敌人数量不变，重新分组） |
| 跨队关系 | 不共享情报；只有同一小队共享最后已知位置 |
| 队长死亡 | 剩余成员降级为"独立"，不再包抄，只做原地防守 |
| 全队死亡 | 正常计入剩余敌人数 |

### 2.3 角色槽位

| 槽位 | 距离 | 行为 | 进入条件 | 退出条件 |
| --- | --- | --- | --- | --- |
| 压制 Suppress | 10–18m | 保持视线、点射/短连发、逼玩家缩掩体 | 有视线且有掩体 | 失去视线 >2s / 换弹 / 弹药 <30% |
| 包抄 Flank | 4–12m | 走侧翼导航点，绕到玩家侧后 | 存在可用侧翼路径且玩家未直视 | 到达侧翼点 / 路径被阻断 / 血量 <35% |
| 支援 Support | 跟随队长 3–8m | 掩护射击、补位、报告位置 | 默认槽位 / 其他槽位已满 | 有槽位空缺时 2s 后补位 |

**槽位分配规则**（每 3s 评估一次，按顺序判定）：

1. 血量 <35% 的成员强制进入 `Retreat`，不占槽位。
2. 小队内至少保留 1 名 `Suppress`；若无人有视线，最近的成员转 `Flank` 寻找角度。
3. `Flank` 最多 1 人；小队人数 ≥3 时第三人为 `Support`。
4. 玩家直视 `Flank` 成员超过 1.5s，且该成员没有掩体 → 退回 `Suppress` 或换侧翼点。
5. 槽位切换有 0.5s 的"决策停顿"，避免每帧抖动。

**受伤后撤**：

- 触发：血量 <35%，且 8m 内有可用掩体。
- 行为：退到掩体后 4s，期间不还击；由 `Support` 提供压制。
- 冷却：同一成员 20s 内只能后撤一次；无掩体时死战。
- 后撤不是回血，血量不恢复。

### 2.4 状态机（在现有四态上扩展，不重写）

```
Patrol ──看见/听见──> Alert ──确认──> Combat ──失去目标──> Search ──> Patrol
                                      │
                                      ├─ 槽位任务：Suppress / Flank / Support
                                      └─ 血量 <35% ─> Retreat（Combat 子状态）
```

- **不新增顶层状态**，`Suppress / Flank / Support / Retreat` 都作为 `Combat` 下的槽位任务，降低回归风险。
- `Retreat` 只是带时限的子状态，结束后回到 `Combat` 并转为 `Support`。
- `Alert` 阶段小队共享一次"疑似位置"，`Combat` 阶段共享"最后已知位置"。

### 2.5 小队共享感知

| 项 | 规则 |
| --- | --- |
| 共享内容 | 玩家最后已知位置、警戒等级、当前槽位 |
| 共享延迟 | 发现者 "喊话" 0.8s 后同步给队友 |
| 位置衰减 | 每 1s 置信度 -0.5；置信度 <0.3 时只保留大致方向 |
| 共享半径 | 同一小队无限；不同小队不共享 |
| 听觉共享 | 枪声/脚步只提升本小队警戒，不跨队 |

### 2.6 同屏开火控制

| 难度 | 同时开火人数 | 令牌持有时间 | 备注 |
| --- | --- | --- | --- |
| 简单 | 1 | 2.0s | 其余只移动与掩护 |
| 普通 | 2 | 2.5s | 默认 |
| 困难 | 3 | 3.0s | 仍受小队人数限制 |

- 令牌由 `CombatDirector` 分配，换弹、失去视线、弹药不足时立即释放。
- 未被分配令牌的敌人不会"站着不动"，而是做侧翼移动、换掩体、喊话。
- 目的：零回血下避免被 3 人同时集火瞬间秒杀。

> **2.0 没有子弹时间**，枪战节奏的松紧完全由本节控制：令牌数量、持有时间、包抄提示、后撤冷却共同决定"压力何时升高、何时给玩家呼吸窗口"。后续任何战斗节奏问题都在这四个参数里调，不引入时间缩放类能力。

### 2.7 行为提示

| 事件 | 表现 | 冷却 |
| --- | --- | --- |
| 敌人开始包抄 | 无线电："有人绕后。" + 屏幕边缘红色箭头（0.6s） | 8s |
| 敌人后撤 | 拟声词 "TCH!" + 脚步方向音 | 5s |
| 小队求援 | 无线电："需要支援！" | 15s |
| 玩家被压制 | 屏幕轻微暗角 + 子弹掠过音 | 3s |

- 提示只给方向与类别，不给精确位置，避免变成透视。

### 2.8 可调参数与数据文件

`res://data/enemies/squads/<chapter_id>.tres`（`SquadConfig : Resource`）：

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `squad_id` | String | — | 唯一 ID |
| `max_size` | int | 3 | 2–3 |
| `flank_max` | int | 1 | 包抄人数上限 |
| `suppress_min_range` / `max_range` | float | 10 / 18 | 压制距离 |
| `flank_min_range` / `max_range` | float | 4 / 12 | 包抄距离 |
| `retreat_health_ratio` | float | 0.35 | 后撤阈值 |
| `retreat_cooldown` | float | 20 | 后撤冷却 |
| `share_delay` | float | 0.8 | 情报共享延迟 |
| `slot_review_interval` | float | 3.0 | 槽位评估间隔 |
| `flank_abort_look_time` | float | 1.5 | 被直视放弃包抄 |

### 2.9 AI 可视化调试

- `F3` 开关 `AIDebugOverlay`。
- 显示内容：当前顶层状态、槽位、目标点、最后已知位置、共享情报半径、令牌持有者、后撤冷却。
- 颜色：压制=黄、包抄=蓝、支援=绿、后撤=灰、无令牌=白框。
- 控制台命令（仅调试构建）：`ai_debug 1`、`ai_squads`、`ai_tokens`。
- 超时兜底：同一槽位任务持续 >12s 无进展，强制重新评估。

### 2.10 验收标准

1. 任意小队在玩家视野内不会出现两人同槽位、三人同时开火（普通难度）。
2. 包抄成员至少有一次从玩家侧后方 120° 方向进入 10m 内。
3. 受伤成员能成功后撤并在 4s 后由队友接替火力。
4. 关闭 AI 后无空引用、无卡死；单关 30 分钟不出现敌人原地抖动。

## 3. 潜行深度

### 3.1 目标与结构

每关增加一条**不经过主交火区**的支路，并与主线在固定节点汇合；哨位分为"可绕开 / 必须处理"；警报分三级，给玩家脱离空间。

### 3.2 三关路线概念

> 章节 2、3 的现有布局未在文档中记录，下面的坐标与长度标"待定"，需要进场景实测后补。

| 章节 | 支路概念 | 入口 | 汇合点 | 待定内容 |
| --- | --- | --- | --- | --- |
| 港口 | 塔身外侧脚手架 → 运输臂下方检修梯 → 货场北侧仓库屋顶 | 塔顶平台西侧护栏缺口 | 地面仓库后门（主交火区北侧） | 检修梯具体坐标、屋顶承重平台尺寸 |
| 赤蛇工厂 | 屋顶通风管 → 二层反应釜走廊 → 地下排污通道 | 工厂外墙消防梯 | 主车间控制室（Boss 前区域） | 通风管入口坐标、排污通道连通性 |
| 铁锚据点 | 船坞外侧栈道 → 干船坞底部 → 修船厂吊车轨道 | 据点外围防波堤 | Boss 场前闸门 | 干船坞底部水位/碰撞、吊车轨道高度 |

### 3.3 哨位分类

| 类型 | 数量（每关） | 行为 | 玩家选择 |
| --- | --- | --- | --- |
| 可绕开 | 4–6 | 固定巡逻，视野窄 | 等时机或制造声响引开 |
| 必须处理 | 2–3 | 卡住支路关键节点 | 暗杀或环境击杀 |
| 队长 | 1 | 携带无线电，死亡会短暂提升全队警戒 | 优先暗杀 |

> 具体数量按现有敌人重新分配，不新增敌人；待关卡实测后填表。

### 3.4 警报三级

| 等级 | 触发 | 持续 | 敌人行为 | 升级条件 |
| --- | --- | --- | --- | --- |
| L0 局部警戒 | 单次可疑声响 / 看到尸体 | 8s | 最近小队向可疑点搜索 15m | 发现玩家或尸体 |
| L1 搜索 | 玩家被看见但脱离视线 | 30s | 全关小队向最后位置搜索，增援 2 人 | 30s 内再次被看见 |
| L2 升级增援 | L1 未解除且再次暴露 | 90s | AlertDirector 刷 1 波增援（按高度层） | 清空增援或脱离 90s |

- L2 结束后回到 L0，不永久锁定。
- 玩家完全脱离视野并静止 10s，可主动降低一级。

### 3.5 尸体与痕迹

| 项 | 规则 |
| --- | --- |
| 尸体 | 暗杀/处决留下 `CorpseMarker`，4m 内敌人可见 |
| 发现尸体 | 3s 迟疑后提升到 L0，并向尸体位置聚集 |
| 藏尸 | 靠近阴影区按交互键拖入，耗时 1.5s，移动速度 1.5m/s |
| 血迹 | 仅表现，不参与判定（避免过度复杂） |
| 环境击杀 | 爆炸桶 / 吊货不产生尸体，只产生声响 |

### 3.6 潜行可读反馈

- 敌人头顶：`?`（可疑）→ `!`（发现），持续 1.2s。
- 屏幕中央：警戒眼睛图标，三档填充。
- 声音：发现音、搜索哨声、增援警报，全部程序生成。
- HUD 不显示敌人位置，只显示当前警戒等级。

### 3.7 数据与脚本

| 数据 | 路径 |
| --- | --- |
| 潜行支路节点 | `res://data/stealth/<chapter_id>_route.tres` |
| 哨位配置 | `res://data/stealth/<chapter_id>_posts.tres` |
| 警戒参数 | `res://data/stealth/alert_config.tres` |

| 脚本 | 职责 |
| --- | --- |
| `StealthDirector.cs` | 支路状态、尸体注册、警戒等级迁移 |
| `AlertDirector.cs`（扩展） | L2 增援节奏、按高度层刷人 |
| `CorpseMarker.cs` | 尸体可见性、被发现计时、拖拽 |
| `StealthHud.cs` | 警戒眼睛、`?`/`!` 图标 |

### 3.8 验收标准

1. 三关都能在不进入 L2 的情况下通关。
2. 支路全程不与主交火区共享视线；汇合点前有至少一个掩体。
3. 尸体被发现会提升警戒；藏尸后不再触发。
4. 被发现的玩家可以脱离并回到 L0，不需要重开。

## 4. 叙事与演出

### 4.1 三帮派视觉符号

| 帮派 | 主色 | 符号 | 口号 | 出现章节 |
| --- | --- | --- | --- | --- |
| 盐帮 | 盐白 + 冷蓝 | 六角盐晶 | "潮水会带走痕迹" | 港口 |
| 赤蛇会 | 血红 + 黑 | 盘蛇环 | "烧干净，就没有证据" | 赤蛇工厂 |
| 铁锚帮 | 铁锈橙 + 深灰 | 锚与断链 | "锚沉下去，人也沉下去" | 铁锚据点 |

- 符号只出现在涂鸦、集装箱喷漆、收集品与 UI 章节标题，不做新 3D 资产。

## 5. 天赋系统

### 5.1 设计原则

- **改变玩法，不做百分比微调**：每个节点都要带来新的动作、路线或战斗方式。
- **三条线互不影响**：点数独立发放、独立消费。
- **不触碰零回血**：没有任何节点提供回血、护盾或吸血。
- **尊重章节解锁**：武器大师只影响当前章节已解锁的武器。

#### 5.2.1 激光剑气细则

| 项 | 值 |
| --- | --- |
| 解锁节点 | A7（需要 A4 处决延伸） |
| 可用章节 | **第三章·铁锚据点起**；港口与赤蛇工厂内节点置灰，不可加点也不可释放 |

**章节限制的处理方式**：采用**锁章节解锁**，而不是"后期关卡才能用"的隐性规则——港口与工厂里 A7 节点显示为锁定（需要通关第二章后才可点），第三章起常驻可用。这样"港口章节只有手枪与近战"的约束不被破坏，玩家也不会在前期拿到一把事实上的远程武器。

### 5.3 加点资源

- 资源名：**天赋点**，按线独立记账（`mobility_points` / `weapon_points` / `assassin_points`）。
- 来源：仅来自章节评级（§6），不做击杀掉落、不做收集品奖励。
- 结算时即时入账，入档后可在主菜单或章节间加点。

**入口（2026-11 裁决，方案 B）**：

| 入口 | 权限 | 说明 |
| --- | --- | --- |
| 暂停菜单「天赋（查看）」 | 只读 | 关卡中途只能查看进度，不能加点或重置 |
| 胜负结算面板「天赋（加点 / 重置）」 | 可加点、可重置 | 胜利与失败结算都提供；失败结算视为重试前调整 |

- 关卡中途没有任何加点入口；失败后先调整天赋再重开，属于结算页行为，不违反"中途不可改"。`Enter` 仍默认走下一章 / 重开，天赋入口需手动聚焦。

### 5.4 天赋重置

| 项 | 规则 |
| --- | --- |
| 允许时机 | 主菜单或章节开始前；**关卡中途不可重置**（暂停菜单只读） |
| 重置范围 | 单条线重置，不提供全清 |
| 退还 | 该线已投入点数全额退还 |
| 代价 | **三条线各自前 `free_resets` 次免费**；之后每条线每次扣 `point_cost` 点（从该线扣除，最低扣到 0） |
| 免费次数 | 按线独立计数（`talent_resets.<line>`），不全局共享；重置机动线不会消耗武器大师线的免费次数 |
| 默认方案 | `free_resets = 1`、`point_cost = 2`、`allow_mid_chapter = false` |
| 已点节点 | 清空该线后重新校验前置；不保留任何依赖该节点的临时状态 |
| 存档 | 重置后立即写入 `save_v2.json` |

- 代价写成可调参数，放在 `res://data/talents/reset_config.tres`（`TalentResetConfig : Resource`：`free_resets`、`point_cost`、`allow_mid_chapter`）。
- 默认方案的取向：鼓励尝试、不惩罚实验；一次免费足够玩家试错，之后扣 2 点形成轻量成本，但不至于让人不敢洗点。

## 7. 武器库

### 7.1 规则

### 7.3 对平衡的影响

- **跨章武器除港口外不限制**：后期已解锁的武器可以带入前面章节重玩；港口是固定例外，任何入口都只有 P-9 + 刀。

- 2026-11 裁决：港口重玩与首次通关一律 P-9 + 刀，跨章武器在港口不生效；不再保留"重玩禁用跨章武器"开关，其余章节维持不限制。
- W6 不生成实体弹药包：击杀后直接给当前枪备弹 +4，避免与原有弹药包掉落产生叠加歧义。

## 8. Boss（第三章 · 铁锚帮）

### 8.1 定位

Boss：**霍克**，铁锚帮头目。场地为修船厂干船坞，30×30m，4 根承重柱、2 个高处锚环（钩锁点）、1 台可破坏的锚机。

> 实现落地（2026-11）：场地取铁锚据点主院北半区，中心 (0, 0, -17)，x∈[-15, 15]、z∈[-32, -2]；南侧闸门 z=-2 留 6m 通道，北侧沿用既有围墙，东西用矮护栏避开 x=±15 的屋顶坡道。4 柱为半高 ×2（(-6,-8)/(6,-8)）与全高 ×2（(-6,-26)/(6,-26)）；锚机 (0, 0, -29)；2 个锚环 (-12, 7, -17)/(12, 7, -17)，正下方各有一个 2×2m 高处落点（落差 3.85m）。场地沿用据点既有 NavMesh，闸门内不再摆放敌人或道具。

### 8.5 失败与重试

## 12. 风险与信息缺口

### 12.1 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 协同 AI 让零回血更难 | 玩家被包抄即死 | 火力令牌、包抄提示、简单难度只允许 1 人开火 |
| 天赋破坏关卡节奏 | 钩锁/二段跳绕过设计路线 | 锚点白名单；二段跳后重验缺口；不做无限制飞行 |
| 潜行与零回血冲突 | 一次失误直接重开 | 三级警报 + 脱离机制 + 尸体可控 |
| Boss 与天赋强度失配 | 点满天赋后 Boss 秒杀 | 弱点倍率与血量按"满天赋"上限校验 |
| 存档引入回归 | 章节解锁/评级错乱 | 存档带版本号；单元测试覆盖迁移 |
| 武器库破坏前期难度 | 后期枪打港口 | 港口固定 P-9 + 刀，跨章武器在港口不生效；其余章节不限制，评级只发一次 |
| 没有子弹时间兜底 | 协同参数调错时，压力无法靠时间缩放补救 | 令牌数量/持有时间/包抄提示/后撤冷却四项作为唯一调节杠杆；M1 验收必须覆盖压力曲线 |

### 12.2 已确认结论（本轮定稿）

| 问题 | 结论 |
| --- | --- |
| 三维分开还是合成总评 | **分开评级**，各自发点，结算展示三枚徽章 |
| 点数发放 | **按历史最佳只发一次**；重玩提升评级时只补差额，同评级不重复发 |
| 天赋重置 | **可以重置**；只能在章节外重置，默认前 1 次免费、之后每次扣 2 点，参数见 §5.4 |
| 四项能力取舍 | **砍掉子弹时间**；钩锁、二段跳、激光剑气三项必做 |
| 难度与评级 | **难度不影响评级**：阈值固定，不区分难度 |
| 跨章武器 | **港口例外**：任何入口进入港口恒为 P-9 + 刀，跨章武器在港口不生效；其余章节不限制，按章节阈值给分，后期武器打前面关卡不加分也不扣分 |
| Boss 战统计 | **计入击杀类指标**（武器大师）；**不计入高度类地形指标**（机动的动作密度/垂直位移）；时间仍计入 |
